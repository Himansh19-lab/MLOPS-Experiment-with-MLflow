# MLflow — Experiment Tracking & Management

MLflow is a powerful open-source platform for tracking and managing machine learning experiments.

It helps you record **what you used, how the model performed, what it produced, and which model version you want to keep**.

A simple mental model is:

```text
MLflow
│
├── Parameters → What did I configure?
├── Metrics    → How well did it perform?
├── Artifacts  → What did it produce?
├── Models     → What model did I train?
├── Tags       → What describes this run?
└── Run Info   → When and where did it run?
```

---

# 1. Metrics

**Metrics are numerical values that describe model performance.**

MLflow allows you to record metrics for every experiment run and compare them across runs.

## Accuracy

Accuracy measures the percentage of predictions that are correct.

```python
mlflow.log_metric("accuracy", accuracy)
```

Example:

```text
Run 1 → Accuracy = 0.82
Run 2 → Accuracy = 0.87
Run 3 → Accuracy = 0.91
```

This makes it easy to identify which experiment performed better.

---

## Loss

Training and validation loss can be tracked during model training.

```python
mlflow.log_metric("train_loss", train_loss)
mlflow.log_metric("val_loss", val_loss)
```

This is particularly useful for neural networks and iterative training algorithms.

---

## Precision

```python
mlflow.log_metric("precision", precision)
```

Precision is useful when false positives are important.

---

## Recall

```python
mlflow.log_metric("recall", recall)
```

Recall is useful when false negatives are important.

---

## F1-Score

```python
mlflow.log_metric("f1_score", f1)
```

F1-score combines precision and recall into a single metric.

---

## AUC

AUC (Area Under the ROC Curve) can be logged for classification models.

```python
mlflow.log_metric("auc", auc)
```

---

## Custom Metrics

Any numerical value can be logged as a custom metric.

Examples:

```python
mlflow.log_metric("rmse", rmse)
mlflow.log_metric("mae", mae)
mlflow.log_metric("r2_score", r2)
```

General syntax:

```python
mlflow.log_metric("metric_name", metric_value)
```

---

# 2. Parameters

**Parameters describe how an experiment was configured.**

They commonly include model hyperparameters, data-processing settings, and feature-engineering choices.

---

## Model Hyperparameters

Examples:

```python
learning_rate = 0.001
max_depth = 10
n_estimators = 100
```

Log them with:

```python
mlflow.log_param("learning_rate", learning_rate)
mlflow.log_param("max_depth", max_depth)
mlflow.log_param("n_estimators", n_estimators)
```

This allows you to compare different configurations.

Example:

```text
Experiment A
learning_rate = 0.001
max_depth = 10

Experiment B
learning_rate = 0.01
max_depth = 20
```

---

## Data Processing Parameters

You can track preprocessing decisions such as:

```text
Train-test split ratio
Random seed
Missing-value strategy
Number of selected features
Scaling method
Encoding method
```

Example:

```python
test_size = 0.2

mlflow.log_param("test_size", test_size)
```

---

## Feature Engineering Parameters

Feature-engineering settings can also be tracked.

Example:

```python
max_features = 5000

mlflow.log_param("max_features", max_features)
```

Other examples:

```text
Feature selection method
Number of generated features
Encoding strategy
Dimensionality reduction settings
```

# 3. Artifacts

**Artifacts are files generated by or associated with an ML experiment.**

Examples include:

```text
Trained models
Plots
Reports
CSV files
Images
Configuration files
Environment files
```

The basic API is:

```python
mlflow.log_artifact("file_path")
```

---

## Trained Models

For supported frameworks, MLflow provides framework-specific model logging APIs.

For scikit-learn:

```python
mlflow.sklearn.log_model(model, "model")
```

This stores the model together with the run.

---

## Model Summaries

You can save model summaries or architecture details.

For example:

```text
model_summary.txt
```

Then:

```python
mlflow.log_artifact("model_summary.txt")
```

---

## Confusion Matrix

A confusion matrix can be generated and saved as an image:

```text
confusion_matrix.png
```

Then logged:

```python
mlflow.log_artifact("confusion_matrix.png")
```

---

## ROC Curves

Save the ROC curve:

```text
roc_curve.png
```

Then:

```python
mlflow.log_artifact("roc_curve.png")
```

---

## Other Plots

Useful experiment plots include:

```text
loss_curve.png
feature_importance.png
prediction_distribution.png
residual_plot.png
```

Log them using:

```python
mlflow.log_artifact("feature_importance.png")
```

---

## Input Data

Datasets can be associated with an experiment.

Examples:

```text
train.csv
test.csv
processed_data.csv
```

However, for large production datasets, it is usually better to use dedicated data/versioning tools such as DVC or object storage rather than duplicating large datasets for every MLflow run.

---

## Scripts and Notebooks

Experiment code can also be stored as artifacts.

Examples:

```text
train.py
experiment.ipynb
```

Example:

```python
mlflow.log_artifact("train.py")
```

---

## Environment Files

Environment information is important for reproducibility.

Examples:

```text
requirements.txt
conda.yaml
environment.yml
```

These can be stored as artifacts:

```python
mlflow.log_artifact("requirements.txt")
```

# 4. Models

MLflow supports model logging for many machine-learning frameworks.

---

## Pickled Models

A serialized model can be stored as an artifact:

```python
import pickle

with open("model.pkl", "wb") as f:
    pickle.dump(model, f)

mlflow.log_artifact("model.pkl")
```

For supported ML frameworks, however, MLflow's framework-specific model APIs are generally preferable because they preserve model metadata and standardized loading information.

---

## Scikit-learn Models

Example:

```python
mlflow.sklearn.log_model(
    model,
    "model"
)
```

---

## ONNX Models

MLflow can also be used with ONNX models for cross-platform deployment scenarios.

---

## Custom Models

Custom models can be logged using MLflow's model interfaces when the model does not fit directly into a standard framework integration.

Example:

---

## Run Tags

Useful run tags include:

```text

Experiment description
Model type
Project
Dataset version
```

Example:

```python

    "experiment_description",
```

---

## Environment Tags


```text
CPU/GPU
Cloud provider
Python version
Project name
Team
Dataset version
```

# 9. Model Registry

The **MLflow Model Registry** provides a centralized way to manage models and their versions.

Conceptually:

```text
Experiment
    │
    ▼
Model Version 1
    │
    ▼
Model Version 2
    │
    ▼
Model Version 3
    │
    ▼
Production Model
```

---

## Model Versioning

Suppose you train multiple versions of a fraud-detection model:

```text
FraudDetection
    ├── Version 1
    ├── Version 2
    └── Version 3
```

Each version can be associated with a different experiment/run.

---

## Model Lifecycle

A typical model workflow might look like:

```text
Development
     ↓
Validation
     ↓
Staging
     ↓
Production
```

> Modern MLflow workflows may use model aliases and tags rather than relying exclusively on older stage-based workflows. The exact approach depends on your MLflow version and deployment architecture.

---

## Model Deployment

The Model Registry can help identify which model version is ready for deployment.

Example:

```text
FraudModel
    │
    ├── v1 → Archived
    ├── v2 → Validation
    └── v3 → Production Candidate
```

# 10. Run and Experiment Details

Every MLflow run contains information about the execution.

---

## Run ID

Each run receives a unique identifier.

Example:

```text
Run ID:
8a7c123456789
```

The Run ID can be used to identify a specific experiment execution.

---

## Experiment Name

Multiple runs can be grouped under a single experiment.

Example:

```text
Experiment:
Customer Churn Prediction
```

Runs could include:

```text
Run 1 → Logistic Regression
Run 2 → Random Forest
Run 3 → XGBoost
Run 4 → Neural Network
```

---

## Timestamps

MLflow records information about when a run started and ended.

This can help determine:

```text
Start time
End time
Run duration
```

Run duration can be useful when comparing computational performance.

# Complete MLflow Tracking Example

The following example demonstrates parameters, metrics, tags, and model logging:

```python
import mlflow
import mlflow.sklearn

from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import (
    accuracy_score,
    precision_score,
    recall_score,
    f1_score
)

model = RandomForestClassifier(
    n_estimators=100,
    max_depth=10,
    random_state=42
)

with mlflow.start_run():

    # -------------------------
    # Parameters
    # -------------------------

    mlflow.log_param("n_estimators", 100)
    mlflow.log_param("max_depth", 10)

    # -------------------------
    # Train
    # -------------------------

    model.fit(X_train, y_train)

    # -------------------------
    # Predict
    # -------------------------

    y_pred = model.predict(X_test)

    # -------------------------
    # Metrics
    # -------------------------

    accuracy = accuracy_score(y_test, y_pred)
    precision = precision_score(y_test, y_pred)
    recall = recall_score(y_test, y_pred)
    f1 = f1_score(y_test, y_pred)

    mlflow.log_metric("accuracy", accuracy)
    mlflow.log_metric("precision", precision)
    mlflow.log_metric("recall", recall)
    mlflow.log_metric("f1_score", f1)

    # -------------------------
    # Tags
    # -------------------------

    mlflow.set_tag("model_type", "RandomForest")
    mlflow.set_tag("experiment_type", "baseline")

    # -------------------------
    # Model
    # -------------------------

    mlflow.sklearn.log_model(
        model,
        "model"
    )
```

# What Does One MLflow Run Contain?

Think of one run as a complete experiment record:

```text
                       MLflow Run
                            │
          ┌─────────────────┼─────────────────┐
          │                 │                 │
          ▼                 ▼                 ▼
     Parameters          Metrics          Artifacts
          │                 │                 │
          │                 │                 ├── Model
          │                 │                 ├── Plot
          │                 │                 ├── Report
          │                 │                 └── Data files
          │                 │
          ▼                 ▼
    Hyperparameters      Performance
          │                 │
          └─────────────────┘

Additional information:

MLflow Run
    │
    ├── Tags
    ├── Run ID
    ├── Experiment
    ├── Timestamps
    └── Source / Environment information
```

# MLflow Tracking Cheat Sheet

| Category | Examples | MLflow Concept |
|---|---|---|
| Metrics | Accuracy, F1, RMSE, AUC | `log_metric()` |
| Parameters | Learning rate, max depth | `log_param()` |
| Artifacts | Plots, CSV, reports | `log_artifact()` |
| Models | Scikit-learn, PyTorch, TensorFlow | Framework-specific `log_model()` |
| Tags | Author, model type, environment | `set_tag()` |
| Runs | Individual training execution | `start_run()` |
| Experiments | Group of related runs | Experiment |
| Model versions | v1, v2, v3 | Model Registry |
| Source | Git commit, scripts | Source/artifact tracking |
| Environment | Dependencies, Python version | Environment metadata/artifacts |

# Key Takeaway

MLflow helps answer the most important questions about an ML experiment:

| Question | MLflow Concept |
|---|---|
| What did I use? | **Parameters** |
| How well did it perform? | **Metrics** |
| What did it generate? | **Artifacts** |
| Which model did I train? | **Model** |
| What does this experiment represent? | **Tags + Run Information** |
| Which model version should I use? | **Model Registry** |

In short:

```text
MLflow
  ↓
Track experiments
  ↓
Compare runs
  ↓
Store models and artifacts
  ↓
Version models
  ↓
Manage the model lifecycle
  ↓
Deploy the right model
```

This makes ML experiments **trackable, comparable, reproducible, and easier to manage in production**.
